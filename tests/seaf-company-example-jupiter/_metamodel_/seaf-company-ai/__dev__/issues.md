### Оценка устоявшихся практик по AI-Native

#### Используемые технологии и инструменты (S2)
Что считаем «устоявшейся практикой»: есть единый стек и его реально соблюдают.
 - Утверждённый стек опубликован и актуализируется. (Да/Нет)
Артефакт: страница/документ «Стек GenAI», дата обновления.
 - Новые проекты стартуют из типовых шаблонов . (Да/Нет) 
Артефакт: шаблонный репозиторий, инструкция «Как начинать».
 - Обязательная проверка соответствия стеку при код-ревью/арх-ревью. (Да/Нет) 
Артефакт: чек-лист ревью, запись в процессах PR/ARB.
 - Опубликованы гайды/курсы по стеку для инженеров и продактов. (Да/Нет) 
Артефакт: ссылки на обучающие материалы/вики, расписание тренингов.
 - Запрещённые/устаревшие инструменты формализованы и блокируются. (Да/Нет) 
Артефакт: перечень «do-not-use», заметки в CI/ревью.

#### Среда исполнения AI-агентов (S3)
Что считаем «устоявшейся практикой»: агенты запускаются единообразно и управляются одинаково.
 - Выбрана и описана единая среда исполнения (рантайм) для продакшн-агентов. (Да/Нет)
Артефакт: страница «Runtime/Environments», матрица сред. 
 - ≥90% продакшн-агентов запущены в этой среде. (Да/Нет) 
Артефакт: список агентов и окружений, дашборд развертываний.
 - Есть стандартизованные процедуры выката/отката релизов агентов. (Да/Нет) 
Артефакт: регламент релизов, чек-лист rollout/rollback.
 - Назначены владельцы сред, описаны роли и зоны ответственности. (Да/Нет)
Артефакт: RACI/контакты в вики.
 - Планы на случай аварий/переносов проверялись за последние 6 мес. (Да/Нет)
Артефакт: запись учений/DR-теста, протокол.
 
#### Межагентское взаимодействие и работа с функциями (S4)
Что считаем «устоявшейся практикой»: агенты говорят «на одном языке», функции централизованы.
 - Принят единый протокол/контракты взаимодействия агентов. (Да/Нет)
Артефакт: спецификация протокола/AsyncAPI/AgentSpec
 - Все новые агенты используют единый реестр функций для вызова функций. (Да/Нет)
Артефакт: записи функций в реестре, примеры вызовов.
 - У каждого агента задекларирован перечень разрешённых функций и прав. (Да/Нет)
Артефакт: карта прав/список функций в описании агента.
 - Есть эталонные шаблоны (примеры) межагентных сценариев. (Да/Нет)
Артефакт: диаграммы взаимодействий, примерные флоу.
 - Процедура добавления/отзыва функции через реестр формализована. (Да/Нет)
Артефакт: регламент FunctionRegistry (add/change/deprecate).

#### Данные для GenAI: RAG / Vector DB / качество (S5)
Что считаем «устоявшейся практикой»: источники и индексы описаны, качество и обновление — по правилу.
 - Единый список источников знаний и векторных индексов с владельцами. (Да/Нет)
Артефакт: каталог RAG/Vector, контакты owners.
 - Для каждого индекса прописана политика обновления (частота, процесс). (Да/Нет)
Артефакт: «RAG refresh policy» в вики/репозитории.
 - Перед публикацией — чек-лист качества данных (валидаторы/семпл-проверки). (Да/Нет)
Артефакт: форма DQ-чек-листа, результаты последнего прогона.

#### Observability: логи / метрики / трейсинг, SLO/SLA (S6)
Что считаем «устоявшейся практикой»: видимость и качество работы агентов понятны «по одному экрану».
 - Определены и собираются ключевые метрики для агентов (ошибки/задержки/качество). (Да/Нет)
Артефакт: перечень метрик на вики, скрин панели.
 - Есть единая панель наблюдаемости по агентам (логи/метрики/трейсы). (Да/Нет)

### Алгоритм определения агентности по стандарту Сбера (генИИ для ДЗО)
Алгоритм определения AI-агентов

ШАГ 1: Если у агента отсутствует любой из указанных в Таблице 1 функциональных блоков, указанных как "обязательный", то такой агент не является AI-агентом в рамках данного стандарта
ШАГ 2: Если у агента логика рассуждения детерминирована (основной алгоритм агента реализован в коде с помощью прямых последовательностей действий if-then), то такой агент не является AI-агентом в рамках данного стандарта
ШАГ 3: Если агент обращается к пользователю за подтверждением каждого промежуточного действия, то такой агент не является AI-агентом в рамках данного стандарта
Если не произошло отсеивание на ШАГАХ 1-3, то такой агент является AI-агентом в рамках данного стандарта, и к нему применимы требования данного стандарта

Из методики оценки агентности Сбера (применяется в банке):
Логика рассуждения агента - варианты (если 1й - то эт не агент):
 - логика рассуждения детерминирована (if-then)
 - недетерминированное построение цепочек рассуждений (в т.ч. планирование) для достижения цели
 - изменение цепочки рассуждений (в т.ч. плана) в зависимости от получаемой информации при достижении цели

Автономность (если 1й - то не агент):
 - агент обращается к пользователю за подтверждением ЛЮБОГО промежуточного действия
 - агент НЕ обращается к пользователю за подтверждением ХОТЯ БЫ ОДНОГО промежуточного действия из своей цепочки
 - агент обращается к пользователю за подтверждением только критичных действий из своей цепочки
 - агент не обращается к пользователю за подтверждением действий  из своей цепочки

Использование инструментов (если 1й то не агент):
 - нет использования  инструментов (обращение в БД, вызовов функций/API или других агентов)
 - агент подставляет параметры из модели в заранее подготовленный запрос (система не формирует структурированный запрос)
 - агент формирует вызов самостоятельно (формирует структурированный запрос)
 - агент самостоятельно может найти / сформировать / создать нужный инструмент (API или другие агенты) и сформировать структурированный запрос


### Варианты LLM приложений (по Сберу):
- Линейный LLM конвейер (детерминированная логика решения задачи, некритичны надежность и производительность, нужна цепочка преобразования данных)
- Традиционная программа + LLM API (детерминированная логика решения задачи, некритичны надежность и производительность, нужно  точечно использовать llm)
- ИИ-агент (автономный LLM агент) - (недетерминированная логика решения задачи, требуется обработка неструктурироанных данных, требуется принятие сложных решений)
- LLM конвейер с обратной связью - (недетерминированная логика решения задачи, требуется обработка неструктурироанных данных, НЕ требуется принятие сложных решений)
- LLM конвейер ветвящийся - (недетерминированная логика решения задачи, НЕ требуется обработка неструктурироанных данных, есть четкая последовательность действий)
- ИИ-агент с контролем - (недетерминированная логика решения задачи, НЕ требуется обработка неструктурироанных данных, нечеткая последовательность действий, допустима вариативность решений)
- Традиционная программа + LLM конвейер - (недетерминированная логика решения задачи, НЕ требуется обработка неструктурироанных данных, нечеткая последовательность действий, нет вариативности решений)
