# Быстрый старт

Цель документа — за 30-60 минут получить первый рабочий контур модели TA, который корректно открывается в реестрах и карточках.

## 1. Что должно получиться в конце

Минимальный результат:

- 1 регион;
- 1 зона доступности;
- 1 ЦОД;
- 1 сегмент сети;
- 1 сеть;
- 1 вычислительный сервис;
- 1 сервер, связанный с сервисом и сетью.

## 2. Минимальные входные данные

Подготовьте до начала:

- список объектов первого контура;
- согласованный префикс ID (например, `myorg.*`);
- ответственного за проверку корректности связей.

Проверьте профиль источников в `../configs.yaml` (блок `seaf.configs -> seaf.company.ta -> data_sources`), чтобы в реестры попадали нужные данные. Для базового старта обычно достаточно `seaf2_only`.

## 3. Базовый маршрут в интерфейсе

После заполнения открывайте по порядку:

1. Локации: регионы, AZ, ЦОДы;
2. Сеть: сегменты и сети;
3. Платформа: вычислительные сервисы;
4. Компоненты: серверы.

Если карточка сервера показывает `location`, `is_part_of` и `subnets`, то базовый контур собран правильно.

## 4. Чек-лист «готово/не готово»

| Проверка | Где смотреть | Критерий готовности |
|---|---|---|
| Локации видны в реестрах | Списки локаций | Все 3 уровня (`region -> az -> dc`) присутствуют |
| Сегмент и сеть связаны | Карточка сети | Заполнены `segment` и `location` |
| Сервис связан с сетью | Карточка вычислительного сервиса | Заполнено `network_connection` |
| Сервер включен в сервис | Карточка сервера | Заполнено `is_part_of` |
| Контур замкнут | Переходы по ссылкам | Можно пройти `server -> service -> network -> dc` без разрывов |

## 5. Частые ошибки на старте

1. Сеть создана без сегмента.
2. Сервер не привязан к сервису (`is_part_of` пустой).
3. Локации у сервиса и сервера конфликтуют.
4. Разные соглашения ID внутри одного контура.

## 6. Следующий шаг

После первого контура переходите к `02_model_filling_start.md` и расширяйте модель слоями. Отдельно настройку конфигурации смотрите в `05_configs_yaml.md`.
