# Инструкция для ИИ-агента

1. **Ознакомься с документацией.** Прочитай `reverse2seaf2/README.md`, `reverse2seaf2/plan.md`, `seaf-company-example-jupiter/Docs/operations_manual.md` и `reverse2seaf2/Docs/get_jsonata.md`. Это базовые правила по перезапуску, JSONata и структуре репозитория.
2. **Разберись с планом.** В `plan.md` есть таблица датасетов и блок «Ближайшие шаги». Начинай всегда с незакрытого шага сверху, отмечай прогресс в `plan.md` и детали в `log.md`.
3. **Валидация JSONata — только через backend.** Любое выражение сначала сохраняй в `_extensions/reverse/dev/jsonata_tests/*`, проверяй `python get_jsonata.py <файл>`, затем фиксируй результат в `reverse2seaf2/log.md`. Никаких POST или локальной отладки.
4. **Обновление датасетов.** После успешной проверки добавляй выражение в `reverse2seaf2/ta/dataset_parts`, пересобирай `_metamodel_/seaf-company-ta/ta/datasets.yaml` (см. `build_datasets.py`, если нужен автосбор), перезапускай docker командой `docker restart archtool_reverse_seaf2` и жди 60 секунд.
5. **Контроль качества.** После перезапуска выполняй обязательный набор запросов: `/core/storage/jsonata/<reverse_dataset>`, `/core/storage/jsonata/<seaf.company.*>`, `/core/storage/problems/`. Затем проверяй UI через MCP Playwright (нужный `entities/.../list`). Скриншоты складывай в `reverse2seaf2/Docs/screenshots` при необходимости.
6. **Логи и документация.** Каждое действие фиксируй в `reverse2seaf2/log.md` (дата, что проверено, идентификаторы curl/UI). Если появляется новый процесс или инструмент, дополняй `Docs/*.md`.
7. **Соблюдай кодировку.** Все файлы сохраняй в UTF-8 без BOM, особенно YAML и инструкции, иначе backend режет выражения.
8. **Не трогай лишнее.** Изменяй только те датасеты/презентации, которые относятся к текущему шагу. Если требуется новое происхождение, добавь отдельный `origin`/`merge`, не ломая существующие.
9. **Будь готов к перезапуску.** Пользователь может перезапускать контейнер/окружение; всегда проверяй актуальность данных после рестарта.
